# Web Development Fundamentals - Live Learning Repository

A collection of small, beginner-friendly HTML examples used for live teaching and practice. Each folder focuses on a foundational concept and keeps examples small enough to inspect and run directly in a browser.

## Topics Covered

- **HTML basics:** document boilerplate and page structure
- **HTML tags:** paragraphs and text styling tags
- **HTML lists:** ordered, unordered, and description lists
- **Anchor tags:** linking between pages and linking to downloadable resources
- **Images:** using images in a page and understanding relative file paths
- **Loading effect:** a small page demonstrating a loading-style visual

## Repository Layout

```text
youtube-live-repo/
├── 01-basics/
├── 02-html-tags/
├── 03-html-lists/
├── 04-a-tags/
├── 05-images/
├── 06-loading-effect/
└── README.md
```

Each numbered folder contains standalone examples. Open an individual `index.html` or other HTML file to study it in the browser.

## Run the Examples

1. Clone the repository:
   ```bash
   git clone https://github.com/Coderudit05/youtube-live-repo.git
   cd youtube-live-repo
   ```
2. Open a lesson folder.
3. Open its HTML file in your browser, or use the VS Code Live Server extension.
4. Change the markup and refresh the browser to observe the result.

No package installation or build step is required for the basic examples.

## Suggested Learning Order

1. Start with `01-basics` to understand the HTML document structure.
2. Explore `02-html-tags` for text content and formatting.
3. Practice list types in `03-html-lists`.
4. Use `04-a-tags` to connect pages and resources.
5. Explore `05-images` to learn image paths and nested folders.
6. Finish with `06-loading-effect` and inspect how the page is structured.

## Learning Goals

- Read and write basic HTML documents
- Use semantic and text-related HTML elements
- Create links between pages
- Understand relative paths for local assets
- Learn by modifying small, focused examples

## Contributing to Your Own Practice

Try changing one concept at a time, then compare the result in the browser. Keep examples minimal and use descriptive filenames so the repository can serve as a quick reference during revision.
